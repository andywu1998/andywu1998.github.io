## 为什么要单独做一篇

飞书文档导入不支持原生 HTML——实测 `<div>`、`<style>` 这类块级标签会被直接丢弃，样式变成裸文字。所以可视化报告在飞书侧只能以**附件**形式提供。

附件信息：

- 文件名：`dg-x5-bpu-service-report-feishu.html`
- 大小：约 22.9 KB
- 形态：自包含单文件 HTML，样式内联、无 JavaScript、无外部依赖
- 用法：下载后用任意浏览器打开，即可看到完整的可视化报告（调用链分层图、数据流九步图、性能对比、两张图实测结果、六问六答）

报告内容概览：

1. 我做了什么——把 X5 的 BPU 封装成常驻 HTTP 推理服务
2. 从 Python 到 BPU 硬件的六层调用链
3. 一张 JPEG 的九步数据流
4. 五个数据契约点
5. 实测性能（yolov8 纯 BPU 9.8 ms、板上端到端 52 ms、4 并发 37.9 req/s）
6. bus.jpg 与扣篮竖图的实测结果
7. 六个问答
8. 八条踩坑清单

## 同步策略：已标记为不同步飞书

本篇笔记在 SQLite 注册表里的 `status` 被标记为 `archived`，含义是**不再向飞书投影**。

原因：飞书文档里含有手工插入的附件块，而自动投影走的是整篇覆盖（`docs +update --command overwrite`），一旦重新同步，附件就会被抹掉。归档之后，投影器的行为是：

```text
if note.status != "active":  ->  返回 skipped，完全不碰远端文档
```

所以这篇笔记的飞书文档是「一次成形、之后冻结」的。

维护约定：

- 本地 Markdown 仍是记录载体，但不要再对这篇跑常规同步
- 飞书文档需要改动时，直接在飞书里手工编辑
- 确实需要重新投影时，先把它改回 `active` 再执行同步，同步后记得重新插入附件
