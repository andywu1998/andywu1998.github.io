# 网页日程与飞书日历同源：一处定义、两个目的地

2026-09-22。起点是一个症状：**网页日程里 09-19 之后就空了，飞书日历上却有一片**。查下来不是投影坏了，
是「什么算一条日程」这件事被写了三遍——飞书事件线一套、飞书笔记线一套、网页（Neon）一套，
三套各说各话。工作票在 `.scratch/web-calendar-parity/`（11 张，全部 resolved）。

## 结论

**把「日历条目」提成本地的一等定义，两个目的地都当它的兄弟投影。**

- **一处定义**：本地 SQLite 视图 `calendar_entries`，取合规则只写在 `scripts/calendar_entries.py`，
  事件线与笔记线统一成同一形状（`kind` 区分 `daily` / `note`）。
- **条目范围 = 现在合规 ∪ 已经发出去过**。后半句是关键：日历上的内容是「写出去的历史」，不是
  「现在推导出来的集合」。本地 2026-06 那 78 条事件现在 `calendar_enabled` 全是 0，日历上却写着 77 条——
  只按「现在合规」取，网页永远对不上。
- **两个目的地**：飞书日历（事件线与笔记线合成一个）与 Neon（网页）都消费这份定义。
- **不撤回**：条目一旦发出去就留着（`withdrawn` 的笔记除外）。这一轮不实现任何删除日历的规则。
- **飞书不是数据源**：它只在一条验收对账命令里出现，日常运行、构建、投影都不依赖它。

## 网页那一份

Neon 里的 `calendar_entries` 只是投影，随时可 truncate 重灌；权威源始终是本地 SQLite。
投影脚本 `web/scripts/project-calendar-entries.mjs` 按台账 `entity_projection_state`
（`projection = 'neon'`）增量发，只处理缺失 / 落后 / 失败的条目。

**两个触发点，容错口径相反**：

| 触发点 | 谁在跑 | 缺 `DATABASE_URL` 时 |
| --- | --- | --- |
| 5 分钟定时器 | `scripts/sync_daily_log_outputs.py` 的第三个目的地 | 警告 + 跳过，整体保持绿色 |
| cc-connect `/note` | worker 的 `neon_projection` job | **算失败**：`failure_summary` 点名，三个仓库的 push 一起跳过 |

`/note` 那条路是有人在场的，绿着却看不到东西比红更难查，所以不加容错开关。代价是明确的：
一台拿来记笔记的机器，配好连接串是前置条件。另外，worker 那一步必须用 `bash -lc` 起 `node`——
cc-connect 进程的 PATH 里没有 nvm，裸 `node` 会落到系统的 Node 18，跑不动脚本里的 `node:sqlite`。

## 验收

一条只读命令对差，跑起来才有意义的是「差额都解释得清」：

```bash
python3 scripts/calendar_parity_report.py
```

2026-09-22 收工时（窗口 2025-01-01 起）：

```
本地条目 = 377   日历 = 392   对上 = 376
对上方式: {'ledger': 376}          （100% 走台账，不再需要按内容猜）
只在日历: 16（12 白名单 + 4 重复）  只在本地: 1（本地重复行）
时刻不一致: 19（全是旧脚本的 12:00 兜底）
id 级对不上、内容级对上: 0        没有解释的差额: 0
```

**`id 级对不上` 从 65 归零**，是另一张票的成果：老账里 65 条记录的飞书事件被重建过、id 换了，
一次性全修（有链式证据：日历描述里留着老账那条记录的同步键）。详见
`notes/documents/日历条目 target_id 过期台账.md`。

## 遗留（已立票：`.scratch/web-calendar-parity/issues/12-note-cli-contract.md`）

- **`/note` 的退出码恒为 0**。`runNoteCLI` 无论同步成败都返回 nil，失败只能从 `succeeded` /
  `failure_summary` 看出来。要不要让它非零退出是另一个决定。
- **`/note` 忽略 `dry_run`**。stdin 里传 `"dry_run": true` 也照真实执行（`runNoteCLI` 把参数写死了），
  拿它做冒烟测试会真的写库、真的推仓库。
