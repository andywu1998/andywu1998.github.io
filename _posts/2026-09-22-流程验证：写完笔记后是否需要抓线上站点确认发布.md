# 流程验证：写完笔记后是否需要抓线上站点确认发布

## 结论

不需要。正式笔记的完成判据是「本地 Markdown 写入 + note_id 注册进 SQLite + `note_cli status` 三层 synced + commit & push」；push 之后由 Vercel 自动重建网页版，抓线上站点只会看到旧构建，证明不了这篇笔记。

## 验证过程

- 输入：一条关于「写完笔记后是否要抓线上站点确认发布」的流程疑问，content_type 取 `method`。
- 动作：按 personal-assistant-workflow 的「正式笔记流程」执行四步——写正文、`note_cli create --apply` 注册与投影、`note_cli status` 复核、一个 commit 带上笔记与 `data/daily_log.sqlite3` 并 push。
- 观察：push 之后完成判据即已满足，不需要额外抓站、查部署状态或补跑同步脚本。

## 为什么抓站证明不了发布

- 网页版是构建期从 `notes/` 生成的快照，不是实时数据源。
- push 到 `main` 只是触发 Vercel 重建，重建有延迟，抓到的多半仍是上一版构建。
- 把派生视图当验收标准，等于给系统造出第二个事实源。

来源：SKILL.md 的「完成判据」一节；`codex_personal_assistant/AGENTS.md` 的「Web 版本（web/）」一节。

## 下一步动作

- 之后写正式笔记，停在「三层 synced + push」即可；只有怀疑部署链路本身故障时，才去单独排查 Vercel 构建日志，而不是用它验收笔记内容。
- 若确实需要验收网页展示效果，把它当成独立任务处理，不并入笔记沉淀流程。
